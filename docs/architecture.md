# Architecture

This page records the design the later tickets build on. It is a decision record, not a description
of what exists: today `apps/server` answers `GET /health` and nothing else. Where a section says
"will", the code arrives in its own ticket.

## Who owns what

**The C# server (`apps/server`) owns all flag data and the API.** It is an ASP.NET Core minimal API
on .NET 10. TypeScript stays for the engine, the SDKs, the CLI, the dashboard and the site.

| Piece | Language | Role |
| --- | --- | --- |
| `apps/server` | C# | flag data, the HTTP API, auth, evaluation for clients that ask the server |
| `packages/engine` | TypeScript | flag evaluation, for TypeScript SDKs |
| `packages/cli` | TypeScript | the `featureslash` command; talks to the server |
| `apps/web` | TypeScript | the dashboard; calls the server |
| `apps/site` | TypeScript | featureslash.dev, prerendered |

## Storage

SQLite through EF Core. The path comes from the `FEATURESLASH_DB_PATH` environment variable.
Migrations are generated by `dotnet ef` (never hand-written) and are additive. One self-hosted
process owns one file. Postgres is a later option, not a goal of the first version.

## Auth

`Authorization: Bearer <token>` on every request that is not `/health`.

- **Admin:** a bootstrap admin token is read from the `FEATURESLASH_ADMIN_TOKEN` environment
  variable. It is never stored in the database or the tree.
- **SDK keys:** one set per environment. The server stores only the SHA-256 hash of a key; the
  plain key is shown once, when it is created.
- There are no user accounts yet.

## Evaluation

Evaluation is specified once, in `docs/evaluation.md`, with shared test vectors in
`fixtures/evaluation/`. It is implemented twice, in TypeScript (`packages/engine`) and in C#
(`apps/server`), and both implementations must pass the same vectors.

- **Server-side SDKs** fetch the ruleset from the server and evaluate locally.
- **Other clients** (browsers, mobile, anything without an SDK) ask the server, which evaluates.

## Dashboard

`apps/web` stops being the data owner. It calls the C# server from server functions, so the token
never reaches the browser. The server's address is `FEATURESLASH_API_URL` and the token is read from
the environment. The D1 placeholder table in `apps/web` stays and stays unused.

## Hosting

**Hosting is undecided.** C# does not run on Cloudflare Workers, so the server ships as a container
for self-hosting. No Dockerfile exists yet. The dashboard and the site stay on Workers; the human
steps in `AGENTS.md` (domain, routes, D1, publishing) still apply.

## Build and gate

`apps/server` is two projects, `FeatureSlash.Server` and `FeatureSlash.Server.Tests` (xunit,
`WebApplicationFactory`), wired into Nx with the `@nx/dotnet` plugin. The SDK is pinned to .NET
10.0.402 in `global.json` and `.tool-versions`. `scripts/nx.ts` skips the server, and says so, when
no SDK runs, so a TypeScript-only contributor can still run the gate. A change to `apps/server` needs
the SDK. See `AGENTS.md`.
