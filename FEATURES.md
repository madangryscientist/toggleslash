## Dashboard
- `dashboard-sign-in`: one operator signs in with a password and gets a signed session cookie; every page and server function needs that session, and the page says why sign-in cannot work when its two secrets are not set or it was opened over plain http at an address other than localhost. How to reach it: `/sign-in`. Source: `apps/web/src/routes/sign-in.tsx` `apps/web/src/api/auth.server.ts` `apps/web/src/start.ts`.
- `dashboard-switcher`: pick the project and, where a page needs one, the environment it works on. How to reach it: the switcher on `/`, `/flags/$flag`, `/environments`, `/keys`, `/segments` and `/audit`. Source: `apps/web/src/components/Shell.tsx` `apps/web/src/components/OperatorSwitchers.tsx`.
- `dashboard-flag-list`: list a project's flags with each one's lifecycle stage, search by key, name or tag, turn a flag on or off in the chosen environment, create a boolean flag, and archive a flag; an archived view restores or deletes archived flags. How to reach it: `/`. Source: `apps/web/src/routes/index.tsx` `apps/web/src/components/FlagList.tsx` `apps/web/src/components/ListControls.tsx` `apps/web/src/components/NewFlagDialog.tsx` `apps/web/src/components/ArchiveDialog.tsx` `apps/web/src/components/ArchivedFlags.tsx` `apps/web/src/components/lifecycle.ts`.
- `dashboard-flag-detail`: on one flag, edit its name, description, owner, tags, temporary mark and visibility to client keys; edit its targeting in one environment (on or off, prerequisites, individual targets with context kinds, rules with clauses, the fallthrough as a variation or a percentage rollout bucketed by context kind, and the off variation), with a save refused when someone else changed the flag first; read its history and its usage counts by variation. How to reach it: `/flags/$flag`. Source: `apps/web/src/routes/flags.$flag.tsx` `apps/web/src/components/MetaForm.tsx` `apps/web/src/components/TargetingEditor.tsx` `apps/web/src/components/ServeEditor.tsx` `apps/web/src/components/targeting/PrerequisitesSection.tsx` `apps/web/src/components/targeting/StateSections.tsx` `apps/web/src/components/targeting/RulesSection.tsx` `apps/web/src/components/Activity.tsx` `apps/web/src/targeting`.
- `dashboard-environments`: list, create, rename and delete a project's environments, make an environment's signing key (its private half is shown once), and turn secure mode on or off once a signing key exists. How to reach it: `/environments`. Source: `apps/web/src/routes/environments.tsx` `apps/web/src/components/EnvironmentsPanel.tsx` `apps/web/src/components/EnvironmentRow.tsx` `apps/web/src/components/EnvironmentDialogs.tsx`.
- `dashboard-keys`: list an environment's SDK keys by prefix, create a server or client key whose plain value is shown once, and revoke a key after a confirmation. How to reach it: `/keys`. Source: `apps/web/src/routes/keys.tsx` `apps/web/src/components/KeysPanel.tsx` `apps/web/src/components/KeyDialogs.tsx`.
- `dashboard-segments`: list, create, edit and delete an environment's segments, with included and excluded keys, members of other context kinds, and rules. How to reach it: `/segments`. Source: `apps/web/src/routes/segments.tsx` `apps/web/src/components/SegmentsPanel.tsx` `apps/web/src/components/SegmentDialogs.tsx` `apps/web/src/components/SegmentEditDialog.tsx`.
- `dashboard-audit`: read a project's audit trail, filtered by flag, environment and date, one page at a time. How to reach it: `/audit`. Source: `apps/web/src/routes/audit.tsx` `apps/web/src/components/AuditLog.tsx`.
- `dashboard-ruleset`: read, without editing, the flags as they were under a ruleset hash the server served, for a project and environment given in the URL. How to reach it: `/rulesets/$hash` with `?project=<project>&env=<env>`. Source: `apps/web/src/routes/rulesets.$hash.tsx` `apps/web/src/components/RulesetView.tsx`.

## Command line
- `cli-install`: the `toggleslash` command, installed from npm as `@slashsuite/toggleslash` (version 0.2.0); it needs Bun 1.4 or later. How to reach it: `toggleslash`. Source: `packages/cli/package.json` `FACTS.md`.
- `cli-version-help`: print the CLI and engine version, or the help with every command. How to reach it: `toggleslash --version` (`-v`), `toggleslash --help` (`-h`). Source: `packages/cli/src/cli.ts`.
- `cli-connection`: the server URL comes from `--url`, else `TOGGLESLASH_URL`, else the config file; the admin token comes from `TOGGLESLASH_TOKEN`, else the config file (`$XDG_CONFIG_HOME/toggleslash/config.json`, mode 600), and is never a flag. How to reach it: `--url <url>`, `TOGGLESLASH_URL`, `TOGGLESLASH_TOKEN`. Source: `packages/cli/src/config.ts` `packages/cli/src/cli.ts`.
- `cli-json`: every command that calls the server prints its result as JSON instead of a table. How to reach it: `--json`. Source: `packages/cli/src/render.ts` `packages/cli/src/cli.ts`.
- `cli-exit-codes`: the CLI exits 0 on success, 1 when the server or the network failed, and 2 on a usage error. How to reach it: the exit status of any `toggleslash` command. Source: `packages/cli/src/errors.ts` `packages/cli/src/cli.ts`.
- `cli-config`: save the server URL, and save the admin token read from stdin, in the config file. How to reach it: `toggleslash config set-url <url>`, `toggleslash config set-token`. Source: `packages/cli/src/commands/config.ts`.
- `cli-projects`: list projects and create one, with a name that defaults to the key. How to reach it: `toggleslash projects list`, `toggleslash projects create <key> [--name <name>]`. Source: `packages/cli/src/commands/catalogue.ts`.
- `cli-envs`: list, create, rename and delete (with `--yes`) a project's environments, make an environment's signing key and print its private key once, and turn secure mode on or off. How to reach it: `toggleslash envs list`, `toggleslash envs create`, `toggleslash envs rename`, `toggleslash envs signing-key`, `toggleslash envs secure-mode <key> on|off`, `toggleslash envs delete`, each with `--project <project>`. Source: `packages/cli/src/commands/catalogue.ts`.
- `cli-flags`: list a project's flags (by `--tag`, with `--archived false|true|all`), show one (with its targeting in `--env`), create one (`--name`, `--variations`, `--description`, `--temporary`, `--client-visible`, `--owner`, `--tag`, `--off-variation`, `--fallthrough-variation`), archive it, delete an archived one, turn it on or off in one environment, and read its history (`--env`, `--since`, `--limit`, `--cursor`). How to reach it: `toggleslash flags list`, `toggleslash flags show`, `toggleslash flags create`, `toggleslash flags archive`, `toggleslash flags delete`, `toggleslash flags on`, `toggleslash flags off`, `toggleslash flags history`. Source: `packages/cli/src/commands/flags.ts`.
- `cli-targeting`: print a flag's targeting in one environment as JSON, and replace it from a JSON file or stdin, refused when its `version` is out of date. How to reach it: `toggleslash targeting show <flag>`, `toggleslash targeting set <flag> --file <path>`. Source: `packages/cli/src/commands/targeting.ts` `packages/cli/src/commands/json-file.ts`.
- `cli-segments`: list an environment's segments, print one as JSON, create one (empty or from a file), replace one from a file, and delete one that no flag uses. How to reach it: `toggleslash segments list`, `toggleslash segments show`, `toggleslash segments create`, `toggleslash segments set`, `toggleslash segments delete`. Source: `packages/cli/src/commands/segments.ts`.
- `cli-keys`: create a server or client SDK key (printed once), list an environment's keys by prefix, and revoke one by id. How to reach it: `toggleslash keys create --kind server|client --name <name>`, `toggleslash keys list`, `toggleslash keys revoke <id>`. Source: `packages/cli/src/commands/keys.ts`.
- `cli-tokens`: create a scoped API token for one project with read or write permission and an expiry of 1 to 365 days (printed once), list a project's tokens by prefix, and revoke one by id. How to reach it: `toggleslash tokens create`, `toggleslash tokens list`, `toggleslash tokens revoke <id>`. Source: `packages/cli/src/commands/tokens.ts`.
- `cli-diagnose`: evaluate a flag for a context on the server and print why, now or under a past ruleset hash, without counting usage. How to reach it: `toggleslash diagnose <flag> --project <project> --env <env> (--context '<json>' | --context-file <path>) [--etag <hash>]`. Source: `packages/cli/src/commands/diagnose.ts`.
- `cli-runtime`: print what the server serves for an environment: its ruleset tag, flag count and last change. How to reach it: `toggleslash runtime --project <project> --env <env>`. Source: `packages/cli/src/commands/runtime.ts`.
- `cli-rulesets`: print what the flags were under a ruleset hash an environment served, for all flags or one. How to reach it: `toggleslash rulesets show <hash> --project <project> --env <env> [--flag <flag>]`. Source: `packages/cli/src/commands/rulesets.ts`.

## Server API
- `api-health`: the server answers that it is up and its version, with no token. How to reach it: `GET /health`. Source: `apps/server/ToggleSlash.Server/Program.cs:57`.
- `api-openapi`: the server serves its OpenAPI document with no token; the same document is committed. How to reach it: `GET /openapi/v1.json`. Source: `apps/server/ToggleSlash.Server/Catalogue/OpenApiSetup.cs` `apps/server/openapi/v1.json`.
- `api-projects`: create, list and read projects. How to reach it: `POST /api/v1/projects`, `GET /api/v1/projects`, `GET /api/v1/projects/{project}`. Source: `apps/server/ToggleSlash.Server/Catalogue/ProjectEndpoints.cs`.
- `api-environments`: create, list, read, update (name, secure mode) and delete environments, and make an environment's signing key, whose private half is answered once. How to reach it: `POST /api/v1/projects/{project}/environments`, `GET /api/v1/projects/{project}/environments`, `GET /api/v1/projects/{project}/environments/{env}`, `PATCH /api/v1/projects/{project}/environments/{env}`, `POST /api/v1/projects/{project}/environments/{env}/signing-key`, `DELETE /api/v1/projects/{project}/environments/{env}`. Source: `apps/server/ToggleSlash.Server/Catalogue/EnvironmentEndpoints.cs`.
- `api-flags`: create, list, read and update a flag's metadata, archive and restore it, and delete it. How to reach it: `POST /api/v1/projects/{project}/flags`, `GET /api/v1/projects/{project}/flags`, `GET /api/v1/projects/{project}/flags/{flag}`, `PATCH /api/v1/projects/{project}/flags/{flag}`, `POST /api/v1/projects/{project}/flags/{flag}/archive`, `POST /api/v1/projects/{project}/flags/{flag}/restore`, `DELETE /api/v1/projects/{project}/flags/{flag}`. Source: `apps/server/ToggleSlash.Server/Catalogue/FlagEndpoints.cs`.
- `api-targeting`: read and replace a flag's versioned targeting in one environment, and turn it on or off. How to reach it: `GET /api/v1/projects/{project}/flags/{flag}/environments/{env}`, `PUT /api/v1/projects/{project}/flags/{flag}/environments/{env}`, `POST /api/v1/projects/{project}/flags/{flag}/environments/{env}/toggle`. Source: `apps/server/ToggleSlash.Server/Targeting/ConfigEndpoints.cs`.
- `api-flag-states`: list every flag's on or off state, targeting version and last evaluated day in one environment. How to reach it: `GET /api/v1/projects/{project}/environments/{env}/flag-states`. Source: `apps/server/ToggleSlash.Server/Targeting/FlagStateEndpoints.cs`.
- `api-segments`: create, list, read, replace (versioned) and delete an environment's segments. How to reach it: `POST /api/v1/projects/{project}/environments/{env}/segments`, `GET /api/v1/projects/{project}/environments/{env}/segments`, `GET /api/v1/projects/{project}/environments/{env}/segments/{segment}`, `PUT /api/v1/projects/{project}/environments/{env}/segments/{segment}`, `DELETE /api/v1/projects/{project}/environments/{env}/segments/{segment}`. Source: `apps/server/ToggleSlash.Server/Targeting/SegmentEndpoints.cs`.
- `api-sdk-keys`: create, list and revoke an environment's SDK keys, stored only as a hash and a prefix. How to reach it: `POST /api/v1/projects/{project}/environments/{env}/keys`, `GET /api/v1/projects/{project}/environments/{env}/keys`, `DELETE /api/v1/projects/{project}/environments/{env}/keys/{id}`. Source: `apps/server/ToggleSlash.Server/Auth/ApiKeyEndpoints.cs`.
- `api-scoped-tokens`: create, list and revoke a project's scoped API tokens, stored only as a hash and a prefix. How to reach it: `POST /api/v1/projects/{project}/tokens`, `GET /api/v1/projects/{project}/tokens`, `DELETE /api/v1/projects/{project}/tokens/{id}`. Source: `apps/server/ToggleSlash.Server/Auth/AdminTokenEndpoints.cs`.
- `api-audit`: read a project's audit trail (filter by flag, environment and since, with a limit and a cursor), and one flag's history. How to reach it: `GET /api/v1/projects/{project}/audit`, `GET /api/v1/projects/{project}/flags/{flag}/history`. Source: `apps/server/ToggleSlash.Server/Audit/AuditEndpoints.cs`.
- `api-usage`: SDKs send usage counts, stored as counts only, and an operator reads a flag's counts per environment and variation. How to reach it: `POST /sdk/v1/events`, `GET /api/v1/projects/{project}/flags/{flag}/usage`. Source: `apps/server/ToggleSlash.Server/Usage/UsageEndpoints.cs`.
- `api-diagnose`: evaluate a flag for a context and answer why, now or under a past ruleset hash, recording nothing. How to reach it: `POST /api/v1/projects/{project}/environments/{env}/evaluate`. Source: `apps/server/ToggleSlash.Server/Sdk/DiagnoseEndpoint.cs`.
- `api-runtime`: read an environment's ruleset tag, flag count and last change. How to reach it: `GET /api/v1/projects/{project}/environments/{env}/runtime`. Source: `apps/server/ToggleSlash.Server/Sdk/RuntimeEndpoint.cs`.
- `api-ruleset-lookup`: read what the flags were under a ruleset hash the environment served. How to reach it: `GET /api/v1/projects/{project}/environments/{env}/rulesets/{hash}`. Source: `apps/server/ToggleSlash.Server/Sdk/RulesetLookupEndpoint.cs`.
- `api-sdk-read`: a server key reads the ruleset with an `ETag` and follows a stream of updates; a client key follows a change signal that carries no flag data; either key evaluates flags for a context, a client key only for flags visible to client keys and, with secure mode on, only for a signed context. How to reach it: `GET /sdk/v1/ruleset`, `GET /sdk/v1/stream`, `GET /sdk/v1/changes`, `POST /sdk/v1/evaluate`. Source: `apps/server/ToggleSlash.Server/Sdk/SdkEndpoints.cs`.
- `api-auth`: the admin API takes the admin token or a scoped token as a bearer token, and the SDK routes take a hashed SDK key. How to reach it: `Authorization: Bearer <token>`. Source: `apps/server/ToggleSlash.Server/Auth/BearerAuthenticationHandler.cs` `apps/server/ToggleSlash.Server/Auth/ServerAuth.cs`.
- `rate-limits`: the server limits requests per key in memory, locks out an IP address after repeated failed credentials, caps the open client-key change streams per key and per IP address, sets security headers on every answer, caps a request body at 1 MiB and times requests out after 30 seconds, except `GET /sdk/v1/stream` and `GET /sdk/v1/changes`. How to reach it: every route. Source: `apps/server/ToggleSlash.Server/Limits/RateLimiting.cs` `apps/server/ToggleSlash.Server/Limits/RequestLimiter.cs` `apps/server/ToggleSlash.Server/Hardening/SecurityHeaders.cs` `apps/server/ToggleSlash.Server/Hardening/RequestLimits.cs`.

## Libraries and SDKs
- `npm-engine`: `@slashsuite/toggleslash-engine`, published on npm at 0.2.0, evaluates flags to the shared spec and exports `evaluate`, `createRuleset`, `normaliseContext`, `describeEngine`, `ENGINE_NAME`, `ENGINE_VERSION` and the types `Context`, `SingleContext`, `Ruleset`, `EvaluationResult`, `Reason` and `ErrorCode`. How to reach it: `import { evaluate } from "@slashsuite/toggleslash-engine"`. Source: `packages/engine/src/index.ts` `packages/engine/package.json` `scripts/pack.ts` `.github/workflows/release.yml`.
- `npm-sdk`: `@slashsuite/toggleslash-sdk`, published on npm at 0.2.0, is the TypeScript server SDK: `createClient` keeps an environment's ruleset current over the stream (with polling when it is down), evaluates in process and sends usage counts, and `signContext` signs a context for secure mode; it also exports the types `Client`, `ClientOptions`, `DetailReason`, `EvaluationEvent`, `Hooks`, `SdkErrorCode`, `VariationDetail`, `Clock`, `Fetch`, `ClientStatus`, `StreamState`, `SyncErrorCode`, `Context` and `SingleContext`. Its `"./shared"` entry exports `systemClock`, `linkedController`, `retryAfterMs`, `withTimeout`, `SseParser`, `UsageReporter` and the types `Clock`, `Fetch` and `UsageReporterOptions`. How to reach it: `import { createClient } from "@slashsuite/toggleslash-sdk"`, `@slashsuite/toggleslash-sdk/shared`. Source: `packages/sdk/src/index.ts` `packages/sdk/src/shared.ts` `packages/sdk/package.json` `scripts/pack.ts` `.github/workflows/release.yml`.
- `npm-sdk-browser`: `@slashsuite/toggleslash-sdk-browser`, published on npm at 0.2.0, is the browser SDK: `createBrowserClient` asks the server to evaluate for one context, caches the answer, re-evaluates when the change signal says flags changed, and fires `change`; it also exports the types `BrowserClient`, `BrowserClientOptions`, `Context`, `ContextEntry`, `ErrorCode`, `MultiContext`, `Reason`, `SingleContext`, `VariationDetail`, `Clock` and `Fetch`. How to reach it: `import { createBrowserClient } from "@slashsuite/toggleslash-sdk-browser"`. Source: `packages/sdk-browser/src/index.ts` `packages/sdk-browser/package.json` `scripts/pack.ts` `.github/workflows/release.yml`.
- `npm-sdk-otel`: `@slashsuite/toggleslash-sdk-otel`, published on npm at 0.2.0, exports `createTracingHooks` and the type `TracingOptions`: an SDK hook that adds each evaluation and the ruleset hash to the active OpenTelemetry span. How to reach it: `import { createTracingHooks } from "@slashsuite/toggleslash-sdk-otel"`. Source: `packages/sdk-otel/src/index.ts` `packages/sdk-otel/package.json` `scripts/pack.ts` `.github/workflows/release.yml`.
- `npm-sdk-openfeature`: `@slashsuite/toggleslash-sdk-openfeature`, published on npm at 0.2.0, exports `ToggleSlashProvider`, a server-side OpenFeature provider over the TypeScript server SDK's client. How to reach it: `import { ToggleSlashProvider } from "@slashsuite/toggleslash-sdk-openfeature"`. Source: `packages/sdk-openfeature/src/index.ts` `packages/sdk-openfeature/package.json` `scripts/pack.ts` `.github/workflows/release.yml`.
- `sdk-csharp`: a C# server SDK (`ToggleSlash.Sdk`, .NET 10) that evaluates flags locally; nothing is published and no registry is named, so it is used from a checkout of this repository by a project reference. How to reach it: `sdks/csharp`. Source: `sdks/csharp/README.md` `sdks/csharp/src`.
- `sdk-go`: a Go server SDK (module `github.com/slashsuite/toggleslash/sdks/go`) that evaluates flags locally; it is not a published package, with no tag and no registry entry, so it is used from a checkout with a `replace` or a `go.work` entry. How to reach it: `sdks/go`. Source: `sdks/go/README.md` `sdks/go/go.mod`.
- `sdk-java`: a Java server SDK (Java 17 or newer) that evaluates flags locally; it is not published and there is no artifact to download, so it is built from a checkout and put on the classpath. How to reach it: `sdks/java`. Source: `sdks/java/README.md` `sdks/java/pom.xml`.
- `sdk-python`: a Python server SDK (Python 3.11 or newer) that evaluates flags locally; it is not published anywhere, so it is used from a checkout of this repository (on `PYTHONPATH`, or `pip install` of the directory). How to reach it: `sdks/python`. Source: `sdks/python/README.md` `sdks/python/pyproject.toml`.
- `sdk-ruby`: a Ruby server SDK (Ruby 3.3 or newer) that evaluates flags locally; it is not published anywhere, so it is used from a checkout of this repository (a `Gemfile` path or the load path). How to reach it: `sdks/ruby`. Source: `sdks/ruby/README.md` `sdks/ruby/toggleslash.gemspec`.

## Self-hosting
- `server-container`: run the server as one container from an image built from this repository, with the admin token from the environment, the SQLite file in the `toggleslash-data` volume and the port on loopback only; no image is published. How to reach it: `TOGGLESLASH_ADMIN_TOKEN=<token> docker compose up -d --build` with `compose.yaml`. Source: `compose.yaml` `apps/server/Dockerfile`.
- `server-from-source`: run the server from a checkout with the .NET 10 SDK. How to reach it: `dotnet run --project apps/server/ToggleSlash.Server`. Source: `apps/server/ToggleSlash.Server/Program.cs` `global.json`.
- `local-stack`: start the server, a seeded shop, the dashboard and the example app on one machine, on loopback, with secrets made per run. How to reach it: `bun run stack`. Source: `packages/e2e/src/stack-cli.ts` `packages/e2e/src/stack.ts` `packages/e2e/src/seed.ts`.
